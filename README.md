# Support Bot — бот для работы с клиентами

Асинхронный Telegram-бот на **aiogram 3**: клиент выбирает услугу и попадает в анонимный чат со специалистом. Ты — единственный админ, друзья видят только свои чаты.

## Возможности

- 👤 Клиент: `/start` → выбор услуги → анонимный диалог (текст, фото, файлы, голос, стикеры)
- 🧑‍💻 Специалист: видит только чаты закреплённых за ним услуг, отвечает кнопкой «Ответить»
- 👑 Админ: полная статистика, список клиентов, все активные чаты, услуги и исполнители
- 🔒 Админ-панель доступна **только** по `ADMIN_ID`; друзья не могут её открыть
- 📊 Статистика: всего клиентов, новых за сегодня, чаты, активные чаты, сообщения, разбивка по услугам и специалистам
- 💾 SQLite-база, webhook для Render/Fly и polling для локального теста
- 📁 Клиентское меню «📁 Мои заказы» — вся история переписки по каждому заказу
- 🔄 Возобновление закрытого чата клиентом («✉️ Продолжить»)
- 🧠 Автоматическое ТЗ из переписки через Gemini («🧠 Собрать ТЗ» у специалиста)
- 📄 Админ проверяет/одобряет ТЗ («📄 ТЗ на проверке»)

## 1. Создай бота у BotFather

1. В Telegram открой [@BotFather](https://t.me/BotFather)
2. `/newbot` → придумай название → придумай username (должен заканчиваться на `bot`)
3. Скопируй полученный токен — он понадобится в `BOT_TOKEN`

## 2. Узнай Telegram ID

- Свой: напиши [@userinfobot](https://t.me/userinfobot) — он ответит цифрой
- Друзьям тоже надо написать туда же и прислать тебе их ID

(После запуска бота ID можно узнать командой `/id` прямо в нём.)

## 3. Локальный запуск

```bash
cd "telegram-bot"
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# открой .env и заполни BOT_TOKEN, ADMIN_ID и SERVICES_JSON
python bot.py
```

Пока `WEBHOOK_URL` пустой, бот работает в режиме polling — этого достаточно для теста.
Напиши боту `/start`, потом `/admin` — проверь админ-панель.

### Настройка услуг (ключевой момент)

В `.env` переменная `SERVICES_JSON` — список услуг с ID исполнителя:

```json
[
  {"key":"site",   "title":"🌐 Разработка сайта", "operator_id": 123456789},
  {"key":"bot",    "title":"🤖 Telegram-бот",     "operator_id": 987654321},
  {"key":"design", "title":"🎨 Дизайн и вёрстка",  "operator_id": 987654321}
]
```

- `key` — короткий идентификатор (латиницей, без пробелов)
- `title` — что увидит клиент кнопкой
- `operator_id` — ID твоего друга; если `0`, чат уйдёт тебе-админу

Другу достаточно просто написать боту `/start`: он попадёт в свою панель и увидит свои чаты. Никаких дополнительных регистраций нет.

## 4. Деплой на Render (бесплатно, $0)

### Что важно знать честно

- Free-план: **0.1 CPU / 512 MB, 750 часов в месяц, без кредитной карты**. Одного сервиса хватает.
- Бесплатный сервис **засыпает через 15 минут без входящих запросов** и просыпается **~1 минуту**. Для бота это лечится бесплатным внешним пингом раз в 10 минут (см. ниже).
- **Файловая система временная**: локальная SQLite-база (статистика) стирается при каждом рестарте, деплое или засыпании. Сама работа чатов от этого не ломается — сбрасывается только накопленная статистика. Постоянная БД на Render платная; если надо сохранять статистику — скажи, подключу внешнюю бесплатную БД (Neon/Turso).
- Render может перезапустить Free-сервис в любой момент.

### Шаг 1 — отдельный GitHub-репозиторий

Папка `telegram-bot` в корневом `.gitignore` портфолио, поэтому нужен свой репозиторий.

1. Создай пустой репозиторий на https://github.com/new, например `retr1kze-support-bot`. **Не** ставь галочки README/.gitignore/license — он должен быть пустым.
2. В терминале:

```fish
cd "/home/retr0/Documents/Default Project/telegram-bot"
git init
git add .
git commit -m "Telegram support bot"
git remote add origin https://github.com/ТВОЙ-ЛОГИН/retr1kze-support-bot.git
git branch -M main
git push -u origin main
```

Если `git push` спросит логин/пароль: паролем GitHub сейчас служит **Personal Access Token** (создать: https://github.com/settings/tokens → *Generate new token (classic)* → права `repo`). Либо просто установи GitHub Desktop и запушь оттуда.

### Шаг 2 — Render

1. Зайди на https://dashboard.render.com → **New → Blueprint**.
2. Выбери созданный репозиторий. Render прочитает `render.yaml`.
3. В форме заполни `sync: false` переменные:
   - `BOT_TOKEN` — токен от BotFather
   - `ADMIN_ID` — свой айди
   - `SERVICES_JSON` — тот же JSON, что в `.env`, одной строкой
4. Plan: **Free**, Region: **Frankfurt**. **Create Web Service**.
5. Через пару минут в логах появится `✅ Webhook: https://retr1kze-support-bot.onrender.com/webhook` — значит вебхук подключён.

`render.yaml` уже содержит `healthCheckPath: /`, `plan: free` и `DB_PATH=data/bot.db`. `WEBHOOK_SECRET` Render сгенерирует сам.

### Шаг 3 — пинг, чтобы не засыпал (обязательно)

1. Зарегистрируйся на https://cron-job.org (бесплатно, без карты).
2. **Cronjobs → Create new**:
   - **URL:** `https://retr1kze-support-bot.onrender.com/`
   - **Request method:** `GET`
   - **Interval:** каждые **10 минут**
3. Включи задание. Альтернатива — UptimeRobot с интервалом 5 минут.

Теперь сервис будет получать входящий запрос чаще, чем через 15 минут, и останется «Live» круглые сутки. Без пинга первое сообщение после простоя может прийти с задержкой ~1 минуту (Telegram повторит вебхук).

### Проверка

Напиши боту `/start` → выбери услугу → отправь сообщение → `/admin` → статистика. В Dashboard у сервиса должно быть состояние **Live**.

## 5. Деплой на Fly.io (с постоянной базой, круглосуточно)

### Про «бесплатно» — честно

У Fly.io нет вечного free-тира, но есть правило: **если счёт личной организации за месяц меньше $5 — его списывают в ноль**. Наш бот выходит в `$2.5–2.7/мес` + копейки за трафик, то есть реально **$0**.

Важные нюансы:

- **Кредитная карта нужна.** Без неё дают только пробный `$1` на 7 дней, и машины во время trials автоматически останавливаются через 5 минут — для круглосуточного бота это не подходит. После привязки карты счёт <$5 обнуляется автоматически, ничего подписывать не надо.
- Счёт идёт на **личную организацию** (создаётся при регистрации). Другие организации waiver не получают.
- Если счёт дотянется до $5 или больше — платишь всю сумму, а не только разницу. Наш конфиг специально самый дешёвый (`shared-cpu-1x`, 256 MB, 1 машина, один маленький том).
- Проверить счёт можно в Dashboard → Billing.

### Шаги

Всё делается в терминале; браузер нужен только для логина!

```bash
# 1. Установи flyctl (одна команда):
curl -L https://fly.io/install.sh | sh

# 2. Войди. Откроется браузер (Firefox). Если не открылся — скопируй ссылку из терминала.
fly auth login

# 3. Перейди в папку бота
cd "/home/retr0/Documents/Default Project/telegram-bot"

# 4. Создай приложение. Если имя занято — придумай другое и замени его ВЕЗДЕ ниже.
fly apps create retr1kze-support-bot

# 5. Создай постоянный диск 1 ГБ в том же регионе, что и primary_region в fly.toml
fly volumes create bot_data --region fra --size 1

# 6. Запиши секреты (токен НИГДЕ не публикуй)
fly secrets set BOT_TOKEN="токен-от-BotFather" ADMIN_ID="свой айди"
fly secrets set SERVICES_JSON='[{"key":"site","title":"🌐 Разработка сайта","operator_id":0},{"key":"bot","title":"🤖 Telegram-бот","operator_id":0},{"key":"design","title":"🎨 Дизайн и вёрстка","operator_id":0}]'
fly secrets set WEBHOOK_SECRET="любая-случайная-строка" WEBHOOK_URL="https://retr1kze-support-bot.fly.dev"

# 7. Деплой. --ha=false = одна машина вместо двух (важно для цены).
fly deploy --ha=false
```

`fly.toml` уже настроен: один инстанс `shared-cpu-1x` 256 MB, автостоп выключен, том `/data` смонтирован, health-check на `/`. Файл `.dockerignore` не даёт локальному `.env` попасть в образ — секреты берутся только из `fly secrets`.

⚠️ **Обязательно задай `WEBHOOK_URL`.** Без него бот уйдёт в режим polling, не поднимет HTTP-сервер, и Fly сочтёт health-check проваленным — деплой не запустится.

### Проверка после деплоя

```bash
fly status        # одна машина, статус started, регион fra
fly logs          # ищи строку ✅ Webhook: https://.../webhook
fly secrets list  # убедись, что переменные на месте
```

Затем в Telegram: `/start` → выбрать услугу → написать сообщение → `/admin` → статистика.

Если нужно перезапустить: `fly apps restart retr1kze-support-bot`.
Если меняешь `SERVICES_JSON` или токен: `fly secrets set ...` — Fly сам перезапустит машину.

## Команды бота

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | Главное меню (клиенту — услуги) |
| `/id` | все | Показать свой Telegram ID |
| `/admin` | только админ | Открыть админ-панель |

## Структура

```
telegram-bot/
├── bot.py            хендлеры, логика чатов, webhook/polling
├── config.py         токен, админ, услуги, база
├── database.py       SQLite: пользователи, чаты, сообщения, события
├── keyboards.py      inline-кнопки
├── requirements.txt  зависимости
├── .env.example      шаблон настроек
├── .gitignore        исключает .env и базу из Git
├── .dockerignore     не пускает .env в Docker-образ
├── render.yaml       деплой на Render (бесплатно)
├── Dockerfile        образ для Fly.io
├── fly.toml          конфиг Fly.io + постоянный том
└── README.md         этот файл
```

## Безопасность

- Токен и ID лежат только в `.env` / секретах хостинга, в `.gitignore` они исключены
- Админские callback-и дополнительно проверяются по `ADMIN_ID` в коде
- Специалист не может ответить в чужом чате — проверяется `operator_id`
- Клиент не видит реальных аккаунтов исполнителей: всё идёт через бота
